# 校準筆記、限制與版本

## 版本
- v0.1.0：依某資訊單位主管的數日對談與案例整理的首版。屬 AI 歸納，部分條目主管尚未逐條確認。

## 限制
1. 資料僅涵蓋有限天數的對談，教育訓練、KPI 審查、跨單位分工、對上簡報、制度與介面設計、進度回報等主題覆蓋較深；採購、人事、資安稽核、廠商管理等領域缺乏素材，遇到時只能用「主管六問」推演並標【AI推論】。
2. 案例中的情境、預算與進度為對談當時狀況，已匿名化，不應視為普遍規則。
3. 部分條目為 AI 摘要，非主管逐字原話。
4. 本 Skill 反映的是特定主管在特定組織的決策偏好，**不同組織需自行調整**。

## 尚待主管校準的事項
- 時效與法遵／資安／安全底線衝突時的優先序。
- 何時由「直接給方向」改為「只問問題」的判斷訊號。
- 如何判斷業務回饋具代表性，避免單一使用者決定全公司規格。
- KPI：自主開發與資訊處支持的創新加分範圍邊界；RAG 測試門檻由誰訂；自主應用成果（提示詞、手冊、影音）的認定邊界。
- 「至少二單位受益」的適用範圍。
- 主管親自介入比例隨團隊成熟度的變化。

## 維護方式
1. 有新對談時，先更新來源筆記，再同步 `core-principles.md`、`case-library.md`。
2. 新原則要標註日期與確認層級；若推翻舊原則，在此頁記錄衝突並請主管校準。
3. 定期檢視本頁「尚待校準」是否已有答案。
4. 使用者回饋「模擬結果與主管實際意見落差」時，收集為反例，作為下次校準素材。
5. 公開版維護原則：新增案例前先去識別化（單位、人名、金額、日期、內部決策細節）。
